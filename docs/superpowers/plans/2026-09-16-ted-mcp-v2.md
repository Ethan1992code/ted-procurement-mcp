# TED Procurement Intelligence MCP V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a deployable V2 data product with CPV discovery, persistence, supplier profiles, sync, daily feeds, and API-key/quota support.

**Architecture:** Preserve V1 service behavior. Add small focused modules for CPV discovery, storage, matching, synchronization, auth, and ASGI deployment; expose them through new MCP tools without coupling core business logic to the MCP SDK.

**Tech Stack:** Python 3.11+, httpx, pydantic v2, MCP Python SDK v2, sqlite3 stdlib, Starlette/ASGI, pytest.

**Spec:** `docs/superpowers/specs/2026-09-16-ted-mcp-v2-design.md`

## Global Constraints
- No production code without a failing test first.
- Preserve all eight V1 tools and behavior.
- No LLM dependency for CPV inference or scoring.
- Bound sync calls to max 20 pages and 250 records/page.
- Never persist or log raw API keys.
- Supabase support uses REST over httpx so no database driver is required.
