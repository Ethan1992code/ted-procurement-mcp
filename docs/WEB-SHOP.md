## 2026-09-23 退款与关单补充

已新增仅服务端操作的 `python -m ted_procurement_mcp.webpay_ops`，无公开退款 HTTP 接口。支持 refund、refund-query、close；真实退款/关单必须先由商户确认具体订单，再通过 --confirm-order 重复该订单号。环境使用服务器私密配置，不在命令中填写密钥。

- 全额退款固定原订单金额；退款编号先持久化，同一订单重试复用该编号。
- 退款发起后至少等10秒再查询；只有 REFUND_SUCCESS 且订单/请求号/金额一致才标记 REFUNDED。超时或未知状态保留 REFUNDING，禁止恢复结果交付。
- 关闭操作先锁定 CLOSING，禁止新支付表单。只有支付宝关闭成功才记录 CLOSED；不存在/超时不算关闭成功。若支付竞争已成功，由原通知/查询恢复 PAID。
- 此工具需要安全服务端环境配置；尚未在生产执行过退款/关单，不代表实际资金链路已验证。

必须在 Supabase 重新执行本次更新后的 schema/webpay.sql（新增一列并更新函数，可重复执行，不删除订单）。45项Python测试通过；本地PGlite通过原10项状态断言和新增12项退款/关单断言。真实浏览器支付、沙箱网页付款、回调和退款仍待验证；WEBPAY_ENABLED 保持关闭。
