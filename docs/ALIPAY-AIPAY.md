## 当前交付范围

新增 `GET /aipay/search?keywords=...`，一次查询最多25条在售采购公告。没有付款凭证时，先在 Supabase 保存订单，再返回 HTTP 402 和签名的 Payment-Needed。携带 Payment-Proof 重试原查询时，使用官方 SDK 验签验付，匹配金额、订单和查询资源，保存检索结果，调用 fulfillment.confirm，确认成功才返回结果及 Payment-Validation。

用户已确认正式售价为人民币1.99元/次查询。上线时设置 ALIPAY_SEARCH_PRICE=1.99，并将支付宝 TED 新服务注册单价设置为1.99元/次；沙箱测试价格不变。此记录不代表生产环境变量已经配置。

空搜索结果也是一次已完成的查询；上线前须在商品说明明确这一点。

原 `/mcp` 的15个工具及原有身份验证保留。这个新增 HTTP 收费入口不等于普通 ChatGPT 连接器自动具备付款能力。面向其他客户销售前，还要完成买方 AI 付客户端接入，以及客户身份/权限方案。不要向客户分享现有所有者密钥或服务端私钥。

## 订单与异常处理

- 持久化订单与结果：`schema/aipay.sql`；使用新 Supabase 项目的 SQL 编辑器执行，当前尚未执行到线上。
- 数据库事务锁、唯一支付宝交易号、90秒生成租约和租约令牌隔离并发请求。
- 确认失败时保留结果，同一凭证重试只确认和返回保存结果。
- TED 查询异常时不确认履约；租约到期后允许原订单在支付截止前重试。进程崩溃时只读查询可能重跑，但只能提交并交付一份结果。
- 已保存的结果可在账单过期后重试确认。未保存结果且已过截止时间的已付异常订单需人工核对处理，不能要求客户盲目重付。
- 支付凭证不写入数据库或日志。SDK异常文本不返回客户端。
- 发布前还须配置平台限流、监控和待确认订单处理流程。

## 配置边界

服务端读取环境变量；不得把真实私钥粘贴到聊天里或提交到仓库。

| 变量 | 含义 |
| --- | --- |
| ALIPAY_ENABLED | 仅精确的 true 才允许启用；当前默认关闭 |
| ALIPAY_GATEWAY | 沙箱或生产官方网关，必须明确指定 |
| ALIPAY_APP_ID | 同一应用的 App ID |
| ALIPAY_APP_PRIVATE_KEY | 原始 PKCS#1 应用私钥，无 PEM 头尾 |
| ALIPAY_PUBLIC_KEY | 该应用对应的支付宝公钥 |
| ALIPAY_SELLER_ID | 2088 开头的实际收款方 ID |
| ALIPAY_SELLER_NAME | 实际商家展示名称 |
| ALIPAY_SERVICE_ID | 沙箱固定 api_mock_service_id；生产为审核通过的服务 ID |
| ALIPAY_SEARCH_PRICE | 商家确认的人民币单次查询价格，最多两位小数 |
| SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY | 服务端数据库配置，沿用新项目 |

缺少配置时收费接口返回503 PAYMENT_NOT_CONFIGURED，不生成账单、不调用支付宝。不会退回固定成功或绕过验付。
